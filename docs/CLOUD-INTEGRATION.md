# Cloud Integration Configuration

## Overview

The Ross Tax Prep frontend application supports integration with multiple cloud monitoring services for enhanced observability and error tracking:

1. **AWS CloudWatch Logs** - Store and analyze error logs
2. **AWS SNS (Simple Notification Service)** - Real-time critical error alerts
3. **Generic MCP Server** - Custom monitoring control plane

## AWS Cloud Integration

### AWS CloudWatch Logs Configuration

AWS CloudWatch Logs provides centralized logging for critical errors with powerful search and analytics capabilities.

#### Required Environment Variables

Set the following in your Cloudflare Pages/Workers environment:

```bash
# AWS Region (e.g., us-east-1, us-west-2)
AWS_REGION=us-east-1

# CloudWatch Log Group (create in AWS Console first)
AWS_CLOUDWATCH_LOG_GROUP=/ross-tax-prep/client-errors

# CloudWatch Log Stream (optional, auto-generated by date if not specified)
AWS_CLOUDWATCH_LOG_STREAM=production-errors

# AWS Credentials (use IAM user with CloudWatch Logs permissions)
AWS_ACCESS_KEY_ID=your-access-key-id
AWS_SECRET_ACCESS_KEY=your-secret-access-key
```

#### Setup Steps

1. **Create CloudWatch Log Group in AWS Console:**
   ```bash
   # Using AWS CLI
   aws logs create-log-group --log-group-name /ross-tax-prep/client-errors --region us-east-1
   ```

2. **Create IAM User with CloudWatch Logs Permissions:**
   - Navigate to IAM > Users > Create User
   - Attach policy: `CloudWatchLogsFullAccess` (or create custom policy)
   - Generate access keys

3. **Set Environment Variables in Cloudflare:**
   ```bash
   # Using Wrangler CLI
   wrangler secret put AWS_ACCESS_KEY_ID
   wrangler secret put AWS_SECRET_ACCESS_KEY
   wrangler secret put AWS_REGION
   wrangler secret put AWS_CLOUDWATCH_LOG_GROUP
   ```

   Or via Cloudflare Dashboard:
   - Workers & Pages > Your Project > Settings > Variables
   - Add each environment variable

### AWS SNS Configuration (Real-time Alerts)

AWS SNS enables real-time notifications for critical errors via email, SMS, or webhook.

#### Required Environment Variables

```bash
# AWS Region
AWS_REGION=us-east-1

# SNS Topic ARN (create in AWS Console first)
AWS_SNS_TOPIC_ARN=arn:aws:sns:us-east-1:123456789012:critical-errors

# AWS Credentials
AWS_ACCESS_KEY_ID=your-access-key-id
AWS_SECRET_ACCESS_KEY=your-secret-access-key
```

#### Setup Steps

1. **Create SNS Topic in AWS Console:**
   ```bash
   # Using AWS CLI
   aws sns create-topic --name critical-errors --region us-east-1
   ```

2. **Subscribe to SNS Topic:**
   - Email: `aws sns subscribe --topic-arn arn:aws:sns:us-east-1:123456789012:critical-errors --protocol email --notification-endpoint alerts@example.com`
   - SMS: `aws sns subscribe --topic-arn arn:aws:sns:us-east-1:123456789012:critical-errors --protocol sms --notification-endpoint +1234567890`
   - HTTPS: `aws sns subscribe --topic-arn arn:aws:sns:us-east-1:123456789012:critical-errors --protocol https --notification-endpoint https://your-webhook.com/alerts`

3. **Configure IAM Permissions:**
   - Attach policy: `AmazonSNSFullAccess` (or create custom policy with `sns:Publish`)

4. **Set Environment Variables in Cloudflare:**
   ```bash
   wrangler secret put AWS_SNS_TOPIC_ARN
   ```

### AWS IAM Policy Example

For production use, create a custom IAM policy with minimal permissions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "arn:aws:logs:us-east-1:123456789012:log-group:/ross-tax-prep/client-errors:*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "sns:Publish"
      ],
      "Resource": "arn:aws:sns:us-east-1:123456789012:critical-errors"
    }
  ]
}
```

## Generic MCP Server URL Configuration (Legacy Support)

The application also supports integration with custom monitoring and control plane (MCP) services.

### Configuration

The `MCP_SERVER_URL` binding is configured in `package.json` and `wrangler.toml` to enable cloud integration.

#### package.json Configuration

```json
"cloudflare": {
  "bindings": {
    "MCP_SERVER_URL": {
      "description": "Base URL of your deployed MCP server endpoint."
    }
  }
}
```

#### Setting the MCP Server URL

**For Cloudflare Workers/Pages:**

1. Set the binding value in your Cloudflare dashboard:
   - Navigate to Workers & Pages > Your Project > Settings > Variables
   - Add a new environment variable: `MCP_SERVER_URL`
   - Value: `https://your-mcp-server.example.com`

2. Or use Wrangler CLI:
   ```bash
   wrangler secret put MCP_SERVER_URL
   # Enter your MCP server URL when prompted
   ```

**For local development:**

Create a `.dev.vars` file in the project root:
```
MCP_SERVER_URL=http://localhost:3001
```

### Features

When cloud monitoring is configured, the application will:

1. **AWS CloudWatch Logs**: Store all critical client-side errors with full context for analysis
2. **AWS SNS Alerts**: Send real-time notifications for critical errors via email, SMS, or webhook
3. **MCP Server Integration**: Forward critical errors to custom monitoring endpoints
4. **Automatic Fallback**: If cloud services are unavailable, logs are stored locally and in the database

### MCP Server API Endpoints

Your MCP server should expose the following endpoints:

#### POST /alerts
Receives critical alerts from the frontend application.

**Request Body:**
```json
{
  "type": "client_error",
  "severity": "critical",
  "message": "Error description",
  "context": "authentication|workflow|task|api",
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

**Response:**
```json
{
  "success": true,
  "alert_id": "alert_xxx"
}
```

### Client-Side Error Logging

The application includes a comprehensive client-side error logging system in `/lib/client-logger.js` that:

1. **Logs errors locally** in localStorage as fallback
2. **Sends errors to backend** via `/api/logs/client`
3. **Forwards critical errors** to MCP server when configured

#### Usage Example

```javascript
import { logAuthError, logTaskError, logWorkflowError } from '../lib/client-logger.js';

// Log authentication errors
await logAuthError('login', error, { email, statusCode: 401 });

// Log task errors
await logTaskError('update', error, { taskId: 'task_123' });

// Log workflow errors
await logWorkflowError('transition', error, { workflowId: 'wf_456' });
```

### Backend Audit Logging

The backend API endpoint `/api/logs/client` (in `/functions/api/client-logs.ts`) receives client-side logs and:

1. Stores them in the `audit_logs` database table
2. Maps log levels to audit severity levels
3. Forwards critical logs to MCP server when configured
4. Captures IP address, user agent, and session information

### Security Considerations

1. **Authentication**: The client logging endpoint accepts Bearer tokens for authentication
2. **Rate Limiting**: Consider implementing rate limiting on the logging endpoint
3. **PII Protection**: Avoid logging sensitive personal information (passwords, SSNs, etc.)
4. **Log Retention**: Configure appropriate log retention policies in your database

### Monitoring Best Practices

1. **Regular Review**: Review error logs regularly for patterns and issues
2. **Alert Configuration**: Configure alerts for critical error rates
3. **Performance Impact**: Client logging is designed to be non-blocking and won't impact user experience
4. **Fallback Strategy**: Local storage serves as fallback when backend is unavailable

### Troubleshooting

**Issue**: Logs not appearing in MCP server
- Verify `MCP_SERVER_URL` is correctly set
- Check MCP server is accessible from Cloudflare Workers
- Review browser console for connection errors

**Issue**: High volume of duplicate logs
- Check for retry logic in error handling
- Verify error handlers are not in loops
- Review rate limiting configuration

**Issue**: Missing context in logs
- Ensure error details are passed to logging functions
- Check that session/user information is available
- Verify error objects contain stack traces
